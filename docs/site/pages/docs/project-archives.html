--- title: Portable project archives description: Transfer exact project evidence with verified inventories, explicit source permissions and safe local bindings. lede: Keep a study's recorded evidence together, inspect what is included, and reopen it in another library. ---

Wave 8 development, slice 10. Use the development host and matching clients (API 2, catalog 2, policy 1). Published v0.7.0 predates portable archives.

Export a study

Open Reports → Portable project archives. Export the current project, history, saved results, available result parents and checkpoints as a .clz file. Original source inclusion is off by default. Include available sources only where permitted; explicitly confirm authority for sources without recorded provider licenses. Restricted provider sources are always omitted.

Captured results may still contain identifiers, sequences and counts. Private-use restrictions require an acknowledgment and remain in the archive notice. This is not de-identification or permission to redistribute data.

Inspect, then import

Choose Inspect project archive, or open a .clz file. Supply a separately retained fingerprint when available. Inspect the full inventory and source statuses, then select Import inspected project. Import checks the fingerprint again, preserves the original project identity and refuses an existing project or conflicting evidence. Use a separate library for an existing identity.

Included sources receive verified local bindings. Omitted, restricted, missing, changed and unsupported sources remain explicit and cannot silently reuse paths on the original computer. Their names and fingerprints remain available for locating matching originals. Download original project evidence retrieves the unchanged source document; the working project contains local paths.

Three observations of one simulated subject, a saved diversity result and a checkpoint were transferred after the original source folder became unavailable. This is a portability check, not a biological finding.

Keep exact evidence distinct from recomputation

Original project/history, result files and checkpoint bytes are preserved. No recipes or scientific workers run during archive inspection or import. Imported checkpoint recovery uses verified local source bindings. The browser refuses a project if its numeric tokens would change when opened.

A matching inventory establishes recorded-byte integrity, not authenticity or biological validity. An independently trusted fingerprint detects substituted evidence. For supported results, exact certificate replay remains a separate operation with its existing input and method limits.

Transfer limits

Archives accept at most 520 MiB compressed input, 512 MiB inventoried bytes, 256 MiB per file, 2,048 payload files, 16 checkpoints and 128 result dependencies. Member paths must meet a bounded portable ASCII contract. Traversal, links, device names, aliases, unlisted files, unsupported versions and changed hashes are refused before installation.

Installed references, caches, running jobs and external outputs are not bundled. Cancellation or interruption may leave unreferenced files; inspect the library before retrying. Undo changes the open project, not files already installed. These are portable studies, not transactional whole-library backups.

The same workflow is available through reviewed automation, MCP, Python and R. See the complete format, source policy, recovery and validation reference.
