MCP clients

A local MCP client drives the same research window and methods. Give it explicit capabilities and review proposed changes before they run.

ClonoLoom 0.8.0. 7.0.

Connect a client

clonoloom mcp --data-dir /absolute/path/to/mcp-library
# Local data, computation and proposed edits:
clonoloom mcp --data-dir /absolute/path/to/mcp-library --allow edits,compute,files

Configure your MCP client's executable and argument array with these values. Default access is read-only. Use one host per library and a dedicated directory. The normal local window opens on the first permitted tool call. With --window none, open the address printed to stderr. Discovery and tool lists need no window. Closing stdin cancels pending work and stops the owned host. stdout is exclusively JSON-RPC.

Review proposed changes

Tool discovery lists only actions allowed by the launch grants. Knowing another action's name cannot widen them. Both HTTP and MCP use the same argument validation, window review, History and bounded audit. Client capabilities and names do not grant application permissions. There is no tool to accept proposals. Read Automation permissions for cancellation, Undo and file-effect limits.

Two explicit protocol modes

MCP 2026-07-28 uses server/discover and per-request protocol/capability metadata. MCP 2025-11-25 uses initialize followed by notifications/initialized. Modern requests never inherit a previous client's label or capabilities. Only tools are advertised; there is no network MCP endpoint, sampling or server-initiated request.

Keep exact results

Text and structured content carry the native result envelope without a floating-point decoding round trip. Typed clonotype queries retain native JSON text, current definition and QC, source units and full-table denominators. Filtering changes membership and displayed rank, without renormalizing frequencies. Use a precision-preserving client decoder and original certificate bytes for exact replay.

MCP adds no scientific method or replay tolerance. Certificate replay keeps its existing five-kind captured-input boundary. Transport success and human acceptance do not prove biological validity or specificity.

Bounds and cancellation

Input frames are at most 2 MiB, arguments 1 MiB and outgoing tool responses 16 MiB. Oversized results return an explicit error, never truncated success; the action may already have completed. At most 16 calls wait concurrently and one window action executes at a time. Request IDs are unique within a process, bounded to 65,536 requests. String IDs/tokens have a 512-byte encoded bound; numeric IDs/tokens must be safe integers.

Optional five-second progress messages measure elapsed waiting time, not percent complete. Cancel by request ID; no later messages are emitted after cancellation is processed. Completed file effects can remain. Reinspect state before resubmitting. Window connection waits are bounded to 40 seconds and window actions to ten minutes. Known live hosts using the same library are refused, but this is not an interprocess lock.

The complete MCP guide includes configuration, protocol examples and precise limits, with links to the official specification. The implementation follows the stdio transport, tools contract and legacy lifecycle.
